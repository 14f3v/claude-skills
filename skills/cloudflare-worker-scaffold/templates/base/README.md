# __PROJECT_NAME__

A Cloudflare Worker (TypeScript + [Hono](https://hono.dev)) scaffolded local-development-first.

## Quick start

```sh
npm install
npm run cf-typegen   # generate worker-configuration.d.ts (binding types)
npm run dev          # local dev server at http://localhost:8787
curl http://localhost:8787/health
```

## Local development — three modes

1. **Pure local** — `npm run dev` (`wrangler dev`). Bindings (KV/R2/D1) are emulated by Miniflare; state lives in `.wrangler/state`, no Cloudflare account needed. For Hyperdrive, the `localConnectionString` in `wrangler.jsonc` connects directly to a database your machine can reach (e.g. a local Postgres).

2. **cloudflared proxy + local** — for a private Postgres behind a Cloudflare Tunnel. Run `./scripts/db-tunnel.sh --hostname db.example.com` to expose it at `localhost:5432`, point `localConnectionString` (or the `CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE` env var) at `localhost:5432`, then `npm run dev`.

3. **Remote** — `npm run dev:remote` (`wrangler dev --remote`). Your Worker runs on Cloudflare's edge using the real deployed bindings (including Hyperdrive → VPC/tunnel → private DB), so no local proxy is needed. ⚠️ Uses live resources/data.

## Secrets

Copy `.dev.vars.example` to `.dev.vars` (gitignored) and fill in local secrets. Never commit `.dev.vars`.

## Deploy

Create the real resources and paste their IDs over the `<...>` placeholders in `wrangler.jsonc`:

```sh
npx wrangler login
npx wrangler kv namespace create KV
npx wrangler d1 create __PROJECT_NAME__-db
npx wrangler r2 bucket create __PROJECT_NAME__-bucket
npx wrangler hyperdrive create __PROJECT_NAME__-hd --connection-string="postgres://user:pass@host:5432/db"
npm run cf-typegen
npm run deploy
```
